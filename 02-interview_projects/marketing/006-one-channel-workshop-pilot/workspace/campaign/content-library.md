# Content library and editorial decisions

## A01 Configuration review checklist

A 500-word checklist already explains how to compare snapshots and log a review owner. It is approved for reuse if the workshop date and CTA are updated from campaign/workshop.md. It has no product screenshots. The strongest section is the example of a changed session timeout: readers can understand the question without owning the product. Do not promise that the checklist detects every security flaw. A content brief can reuse its structure, link to it or propose a focused replacement.

## A02 One-hour lab invitation — archived

This unapproved brainstorm says “join our one-hour live hacking lab and leave with a secure release.” It is retained for editorial context only. E1 in campaign/workshop.md explicitly replaces the duration and format. company/facts.md rejects the secure-release promise. Treat it as an editing starting point if useful, not a factual source. No asset needs to preserve this phrasing.

## A03 Product review note

Ivo's approved internal demo note walks from an old and new configuration to a human review question. A stronger story for an operations audience starts with the decision they must make, then shows a small table of changed settings. The note uses “review aid,” not “automated security approval.” The product still needs a person to understand context. A developer may want the field-level comparison; a manager may want the owner and next check.

## A04 Newsletter slot

The next newsletter has room for one short item, approximately 100–150 words. The slot can teach one idea or invite readers to request a workshop seat. There is no requirement to do both. A useful draft names its intended recipient segment, has one clear action and explains a measurement method. An optional alternative subject line is enough for a test idea; the team cannot run multiple audience experiments this week.

## A05 Website maintenance

The workshop page has a title, summary, agenda, signup CTA and accessibility note. Mina can edit text but cannot ship an interactive calculator or redesigned registration flow this week. A good page brief separates publishable replacement wording from questions requiring an owner. Search metadata must describe the actual workshop. A new page and a repaired existing page are both reasonable ideas if the candidate explains the maintenance cost and intent overlap.
